## 本批交付

OP3-A 中期闭合 B3/W5 双真相源根因：以 agent.yaml runtime 块为唯一可写真相，Registry runtime 块降级为派生缓存 + config_hash 漂移指纹，agentctl repair 受信重建，updateAgent 拒 model 直改，doctor config-drift 检查。不越界到长期破坏性（移除 runtime 块）或 I-5 model 收紧。

### 源码改动

- `src/schemas/registry-schema.ts`：registryAgentSchema 增 `config_hash: z.string().optional()`（在 updated_at 后）。optional 向后兼容既有无 hash 条目；缺失时 doctor 报 config-drift warn，agentctl repair 补齐。
- `src/core/agents.ts`：新增 `computeConfigHash(runtime)`，`sha256(JSON.stringify({provider,locked,model?}))`。**只哈希 runtime 块而非整文件**，避免 archive 写 lifecycle 块、identity doc 变更等合法 agent.yaml 改写误报漂移。`loadPortableConfig` **未动**（I-5 model 收紧属长期范畴，本批禁）。
- `src/core/registry.ts`：`updateAgent` 增 model 直改守卫——`next.runtime.model !== current.runtime.model` 抛 `CONFLICT`（model 须经 resyncRuntime 从 agent.yaml 派生）。grep 确认 4 调用方（factory-application.ts:402/411/437/692）均只动 status/archived/bridge.authorization/updated_at，零破坏。新增 `resyncRuntime(id, runtime, configHash)` 受信重建路径：在 registry.lock 下以 agent.yaml runtime 块刷新缓存 + config_hash，**允许 model 变更**（从 agent.yaml 派生），但 provider/locked 不变量仍 `CONFLICT` 强制（违则不覆盖）。resyncRuntime 是唯一能改 Registry model 的入口，单一可写源由此达成。
- `src/core/create-agent.ts`：`buildRegistryAgent` 返回对象末尾增 `config_hash: computeConfigHash(runtime)`。
- `src/core/backup.ts`：`restore()` 经 `registry.add` 写入时末尾增 `config_hash: computeConfigHash(runtime)`（与 create 对称）。
- `src/application/factory-application.ts`：新增 `repairAgent(id)`。复用 `getAgent(id)`（已 loadPortableConfig 校验 id/provider/locked 与 Registry 一致，故 agent.runtime 可信），算 `computeConfigHash(agent.runtime)`，比对 model/hash 是否变化，调 `registry.resyncRuntime`，返回 `{id, resynced:{model,hash}}`。无重复 loadPortableConfig 调用。
- `src/cli-program.ts`：新增 `agentctl repair <agent-id>` 命令（archive 命令后），输出绿色汇总（model 已从 agent.yaml 同步 / config_hash 已刷新 / 已是最新无变更）。
- `src/core/doctor.ts`：agent-config 检查重构为复用 `loadPortableConfig`（catch null -> fail），并新增 config-drift 检查——`computeConfigHash(portableConfig.runtime) !== agent.config_hash`（或 config_hash 缺失）则 warn，remediation 指向 `agentctl repair <id>`；等则 pass。
