# Skill: Requirement Review

## 使用场景

新功能、行为变化、数据口径、跨模块任务或需求存在歧义时。

## 不适用场景

已明确定位的纯文案、格式或无行为变化的小修正。

## 输入

用户目标、限制、验收描述、相关 handoff/docs/code。

## 执行步骤

1. 区分目标、非目标和外部操作授权。
2. 查找现有产品规则、API、数据字段和相似实现（见 docs/PROJECT_CONTEXT.md、docs/ARCHITECTURE.md、docs/DECISIONS.md）。
3. 列正常、空、错误、权限、兼容和性能场景。
4. 标记「已确认」「从实现推断」「待确认」。
5. 输出可测试的验收条件和影响范围。

## 检查清单

- [ ] 用户口径、日期、环境和数据源明确。
- [ ] 是否改变 API、存储、权限、任务或部署已说明。
- [ ] 破坏性/外部动作已有授权。
- [ ] 未将当前实现误写成最终产品规则。

## 输出

需求摘要、验收条件、非目标、待确认问题、初步影响清单。

## 完成标准

下一步实现无需依赖聊天猜测关键产品选择。

## 常见风险

只看表面不查既有口径；把示例当完整需求；忽略旧数据兼容；未经授权扩大为重构。

## 与其他 Skill 的关系

通常先于 feature-development、bug-fix。
