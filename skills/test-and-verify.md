# Skill: Test and Verify

## 使用场景

任何代码、配置、规范、依赖、构建或部署变更完成前。

## 不适用场景

仅阅读和报告现状时可不运行写入性构建，但仍应使用现有只读证据。

## 输入

改动 diff、验收条件、风险清单和现有测试命令（见 docs/TESTING.md）。

## 执行步骤

1. 将每项风险映射到自动或人工检查。
2. 先跑最小相关测试，快速定位失败。
3. 按任务规模（见 docs/DEVELOPMENT_RULES.md）运行测试、lint、构建、冒烟。
4. 大型或跨模块任务运行完整验证。
5. 检查产物来源、深链（如受影响）。
6. 记录命令、通过数、warning 和未覆盖项。

## 检查清单

- [ ] 正常、空、错误和边界场景覆盖。
- [ ] 回归测试会在错误实现上失败。
- [ ] 没有通过删断言、跳过测试或静默 fallback 造绿。
- [ ] Warning 区分存量和新增。
- [ ] 人工验证步骤可复现。

## 输出

验证矩阵、命令结果、失败原因、已知未覆盖项。

## 完成标准

所有与风险相称的检查通过，未验证部分已明确且不被宣称完成。

## 常见风险

只跑单测不构建；依赖旧产物；重复冒烟未察觉；把存量 warning 当新代码免检。

## 与其他 Skill 的关系

所有实现 Skill 的必需收尾步骤，并为后续发布或交接提供输入。
