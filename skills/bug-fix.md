# Skill: Bug Fix

## 使用场景

已有行为错误、回归、数据错算、崩溃、边界遗漏或性能退化。

## 不适用场景

需求变化或新能力不是 Bug；缺乏可验证现象时先做 requirement-review。

## 输入

复现条件、期望/实际结果、版本、日志、相关数据和测试。

## 执行步骤

1. 最小化复现并确认不是配置/口径误解。
2. 沿调用链定位根因（UI/入口 -> 数据访问 -> 领域逻辑 -> 存储）。
3. 写能在修复前失败的回归测试。
4. 做最小根因修复，不顺带重构无关区域。
5. 验证相邻边界、旧数据和错误路径。
6. 若暴露长期规则缺失，更新 docs/DECISIONS.md。

## 检查清单

- [ ] 根因与症状已区分。
- [ ] 回归测试真实覆盖问题。
- [ ] 未静默吞错、伪造数据或放宽安全限制。
- [ ] 时间、0、大整数、空值和编码边界已检查。

## 输出

根因说明、最小修复、回归测试、验证和剩余风险。

## 完成标准

原复现不再出现，测试可防止同类回归，未改变无关契约。

## 常见风险

只加空判断掩盖根因；用快照固化错误；删除失败断言；把环境数据提交仓库。

## 与其他 Skill 的关系

复杂根因可转大型任务（refactor）；结束使用 test-and-verify 和 task-handoff。
